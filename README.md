# BLE シャッターリモコンで WAV を鳴らす (ESP32)

BLE シャッターリモコン `vyviyon` のボタンを押すと、A2DP 接続した Bluetooth
スピーカー `C06` から `family-mart_3.wav` が再生される。

`ble_mouse_player` を複製し、入力を BLE マウスからシャッターリモコンに
差し替えたもの。音源と再生処理は同じ。

## 部品

| 部品 | 備考 |
|---|---|
| ESP32 開発ボード | Classic Bluetooth 必須。ESP32-S2/S3/C3 は**動作しない** |
| BLE シャッターリモコン | BLE HID のみ対応 |
| Bluetooth スピーカー | |

配線は不要。GPIO 2 のオンボード LED が再生中に点灯する。

## 動作の流れ

1. コントローラを BTDM モードで起動し、Classic と BLE を両方使えるようにする
2. Classic で `C06` に A2DP 接続する。前回繋いだアドレスが NVS にあれば直接
   接続しに行き、なければ名前で探す
3. 接続から 2 秒後に音量 `VOLUME` を設定する。再接続のたびに設定し直す
4. BLE スキャンを開始し、`vyviyon` を名前で探す
5. 見つけたら HID ホストとして接続、ペアリングは Just Works
6. リモコンの入力レポートを受け取り、押下の立ち上がりで再生
7. 押した時にスピーカーが切れていたら、すぐ接続しに行く。繋がった時点で
   頭から鳴る

BLE の開始をスピーカー接続の後にしているのは、ESP32 の無線が1系統しかなく、
Classic の探索と BLE スキャンを同時に走らせると競合するため。ただし起動から
30 秒経ってもスピーカーが繋がらない場合は、待たずに BLE を開始する。
スピーカーが見つからないせいでリモコンまで使えなくなるのを防ぐため。

## 押下の判定

シャッターリモコンはボタンが1個で、押した時と離した時にだけレポートを送る。
ただし何を送るかは機種や iOS/Android 切替スイッチで変わる。

- HID キーボードとして Enter や音量アップのキーコード
- コンシューマコントロールとして音量アップ

そのため `usage` やキーコードでは絞らず、**レポートの全バイトがゼロから
非ゼロに変わった瞬間**を押下とみなしている。

`vyviyon` の実測値:

| 操作 | レポート |
|---|---|
| 押す | `usage=32 id=2 len=2: 01 00` |
| 離す | `usage=32 id=2 len=2: 00 00` |

`usage=32` は `ESP_HID_USAGE_CCONTROL`（コンシューマコントロール）。キーボード
ではない。マウス版の `usage == ESP_HID_USAGE_MOUSE` 判定のままだと全て捨てられる。

40 秒間の連打試験で押下 19 回、離す 20 回、再生も押下と同数。取りこぼしと
二重発火はなかった。

## ビルドと書き込み

1. **ツール > Partition Scheme > Huge APP (3MB No OTA/1MB SPIFFS)** にする。必須
2. リモコンをスマホなど他の機器から削除し、ペアリングモードにする
3. スピーカーをペアリングモードにする
4. 書き込み後、シリアルモニタを 115200 baud で開く

シリアルの想定出力:

```
音源 395718 フレーム / 約 9.0 秒
スピーカーを探しています
スピーカー接続
音量 100
リモコンを探しています
リモコン発見 RSSI -59
ペアリング 成功
リモコン接続 vyviyon
report usage=32 id=2 len=2: 01 00
再生
report usage=32 id=2 len=2: 00 00
```

スピーカーが切れている時に押した場合:

```
report usage=32 id=2 len=2: 01 00
再生
スピーカー未接続、接続を試みる
report usage=32 id=2 len=2: 00 00
スピーカー接続
音量 100
```

ESP32 はスケッチの書き込み後やシリアル記録用のリセットで再起動し、そのたびに
スピーカーとリモコンの接続は一度切れる。普段の使用 (充電器から給電のみ) では
リセットは起きない。

## 設定値

| 項目 | 場所 |
|---|---|
| スピーカー名 | `ble_remote_player.ino` の `SPEAKER_NAME` |
| リモコン名 | `ble_remote_player.ino` の `REMOTE_NAME` |
| BLE を見切りで開始するまでの時間 | `BLE_START_TIMEOUT_MS`（30000 ms） |
| 音量 (0〜127) | `VOLUME`（100） |
| 接続から音量設定までの待ち時間 | `VOLUME_DELAY_MS`（2000 ms） |
| 再接続で鳴らした後、届いた押下を無視する時間 | `WAKE_PRESS_GUARD_MS`（1000 ms） |

名前はどちらも前方一致。リモコン名は大文字小文字を無視する。スピーカー名は
ライブラリ側の照合なので区別する。

## 音量

`VOLUME` は ESP32 側のデジタル音量とスピーカー本体の音量の両方に効く。
ライブラリはスピーカーから音量の通知を受けると、その値で ESP32 側の
`set_volume()` も呼ぶため、2つは連動する。スピーカー本体の音量ボタンでも
調整できるが、再接続のたびに `VOLUME` に戻る。

ESP32 側は指数カーブなので、値を少し下げるだけで大きく減衰する。

| VOLUME | ESP32 側 | スピーカー本体 |
|---|---|---|
| 127 | 0 dB | 100% |
| 115 | -3.4 dB | 91% |
| 100 | -7.7 dB | 79% |
| 90 | -10.6 dB | 71% |
| 80 | -13.5 dB | 63% |

## 待機中の信号 (再生の頭が消える対策)

ESP32 は待機中も A2DP ストリームを開いたまま、音声データを送り続けている。
以前は待機中に完全な無音 (全ゼロ) を送っていたが、そうすると押した直後の
約 1 秒が聞こえなかった。

原因は C06 側の無音ミュート。無音が続くとアンプをミュートし、音が来てから
解除するまでに約 1 秒かかる。再生中にもう一度押すと頭から聞こえる (その時は
ミュートが解除済み) ことで確認した。ESP32 側は先頭から送っていて、ライブラリ
にもフェードインや読み飛ばしの処理はない。

対策として、待機中は 0 の代わりに 30 Hz の正弦波を振幅 100 (約 -50 dBFS、
`VOLUME` 100 の減衰後は約 -58 dBFS) で流している。小型スピーカーは 30 Hz を
ほぼ再生できないので聞こえない。リモコンが押されたら音声ファイルに切り替わる。
振幅 100 で、1 回目の押下から頭まで聞こえ、待機中にノイズも聞こえないことを
確認した。

| 定数 | 値 | 調整の目安 |
|---|---|---|
| `KEEPALIVE_HZ` | 30 | 44100 を割り切れる値のみ。割り切れないとビルドが止まる |
| `KEEPALIVE_AMPLITUDE` | 100 | 頭が消えるなら上げる。「ブーン」と聞こえるなら下げる。0 で無効 |

数程度の極小の振幅では効かない。ESP32 側の音量処理と A2DP の圧縮 (SBC) で
0 に丸められる。

## スピーカーの電源が切れる件

C06 は電源が切れることがあった。原因は電池切れだった。充電してからは勝手に
切れなくなった。当初は無音による自動オフを疑ったが、次の点から電池切れと
判断した。C06 の説明書は見つからず、自動オフの仕様は未確認。

充電後の確認は待機中の信号 (振幅 100) を流した状態で行ったので、信号が自動
オフの防止に効いていないとまでは言い切れない。ただ再生中にも切れていたことは、
自動オフでは説明できない。

- 格安スピーカーのチップ 3 社 (Jieli、Bluetrum、Actions) の開発キットの
  ソースでは、自動オフの条件は「Bluetooth 未接続」か「A2DP ストリームが
  再生中でない」だった。音量は見ていない
- ESP32 は接続中ずっとストリームを「再生中」のまま保つ。ライブラリには
  ストリームを止める処理がない (`BluetoothA2DPSource.cpp:908-910`)
- 音声の再生中にも切れた
- 切れる前に「プッ、プッ」という定期的な音が鳴っていた。電池残量の警告音に
  よくある鳴り方

## つまずいた点

**リモコンの名前がスキャンに出ない**

`vyviyon` は待機中のアドバタイズに名前を載せていない。ボタンを押すと名前付きの
アドバタイズを出し直し、そこで見つかる。検出一覧で確認した。見つからないときは
リモコンのボタンを押す。

**リモコンは放置すると自分から切れる**

最後の押下から 5 分で自分から切断して眠る (実測、説明書の抜粋とも一致)。切れると ESP32 は BLE スキャンを再開し、
ボタンを押すと起きて再接続する。

**長く眠った後、1 回目の押下で鳴らない**

1 時間ほど放置すると、1 回目の押下ではリモコンが起きて繋がるだけで、押下の
レポートは届かなかった。ESP32 は押してから約 1 秒で接続していたので、見つける
のが遅れたわけではない。短い眠りの後は、起こした押下も接続の約 0.3 秒後に届く。

AB Shutter3 系の安価なリモコンで既知の挙動で、ESP32 側で接続を速めても直らない
という報告がある (NimBLE-Arduino の issue #655)。vyviyon の説明書は取得できず、
仕様としての記載は未確認。

眠ったリモコンはボタンを押さない限り起きないので、**一度切れたリモコンが繋がり
直したこと自体を押下とみなして鳴らす**ようにした。

- 起動後最初の接続では鳴らさない。押さなくても起きていたリモコンかもしれない
  ため。そのため電源投入後、長く眠っていたリモコンの 1 回目の押下は鳴らない
- 再接続で鳴らした後 1 秒間に届いた押下は無視する。短い眠りの後に起こした押下
  も届いて、二重に鳴るのを防ぐ
- 電波が悪くて切れ、繋がり直した時にも鳴る

**スピーカーが繋がらない、一度切れると戻らない**

ESP32-A2DP 1.8.11 のソースで確認した挙動:

- 自動再接続 (前回のアドレスへ直接接続) は既定で無効 (`BluetoothA2DPCommon.h:381`)。
  ヘッダーのコメントには既定で有効とあるが、実装と食い違っている
- 自動再接続が無効だと、一度切れた後は二度と探しに行かない。切断後の定期処理は
  「探索に切り替える」とログに出すだけで、何もしない (`BluetoothA2DPSource.cpp:688`)
- 名前での探索は、スピーカーが探索に応答する状態の時しか見つからない。一度
  ペアリングしたスピーカーの多くは、ペアリングモード以外では応答しない

そのため `set_auto_reconnect(true)` を入れ、押下時にも `connect_to()` で接続しに
行くようにした。 起動から約 14 秒で、ペアリングモードにしていない C06 に繋がることを
確認した。うち約 10 秒は、ライブラリが接続前に入れている待ち時間。

**`reconnect()` は使えない**

ライブラリの `reconnect()` は内部状態を `IsReconnecting` に書き換え
(`BluetoothA2DPCommon.cpp:93`)、Source 側にはそれを戻す処理がない。以降、
背景の自動再接続が止まる。`connect_to()` と `get_last_peer_address()` を使う。

**音量が大きすぎた / 小さかった**

`set_volume()` は値が前回と同じだと何もせずに戻る (`BluetoothA2DPCommon.h:240`)。
また接続直後は AVRCP がまだ繋がっていないので、スピーカー本体に音量が届かない。
接続から 2 秒待ち、AVRCP の音量コマンドを直接送るようにした。これで本体にも
届くようになり、127 では大きすぎたので 100 にした。

**スピーカーからの「プッ」というノイズ**

BLE スキャンが無線時間の約 6 割を使っていて、A2DP の音声パケットが欠けていた
可能性が高い。リモコンが寝ている間はずっとスキャンするので影響が大きい。
スキャンの占有率を約 1 割に下げた。

**スピーカーが繋がらない時の切り分け**

ビルド時に **ツール > Core Debug Level > Info**（FQBN なら `DebugLevel=info`）に
すると、ライブラリの接続処理のログが出る。探索で見つかった機器の名前も
`--Name: ...` として出る。C06 の電源が切れていた時は `Y11` という別の機器だけが
見えていた。

## 既知の制約

A2DP のストリーミング中も BLE の接続イベントが同じ 2.4GHz を使う。
7.3 秒の音源の再生では問題は出ていないが、長い音源や電波環境の悪い場所では
音が途切れる可能性がある。

Arduino ESP32 core 3.3.12 の prebuilt ライブラリでは Classic Bluetooth の HID が
無効。Classic 接続のリモコンは使えない。

## 音源の差し替え

`ble_mouse_player` と同じ。16bit PCM 44100 Hz の WAV を置いて次を実行する。

```sh
python3 wav2header.py my_sound.wav sound.h
```

`wav2header.py` と元の WAV はリポジトリに含めていない。スクリプトは
`ble_mouse_player` のものと同一なので、そちらからコピーして使う。

同梱の `sound.h` は `family-mart_3.wav` (8.97 秒) から加工なしで生成した。
395718 サンプル、フラッシュ 791436 バイト。元の音源が RMS -10.3 dBFS と十分な
音量なので、`--drive` はかけていない。かけると 3.0 で 2.5% のサンプルが潰れる。

小さい音源を持ち上げたいときは `--drive` を使う。詳細は
`ble_mouse_player/README.md` を参照。

## 開発環境のメモ

コマンドラインからのビルド、書き込み、シリアル取得の落とし穴は
`ble_mouse_player/README.md` の「開発環境のメモ」にまとめてある。

ここで新たに分かったこと:

**接続中の動作確認はリセットせずに読む**

シリアルを読むためにボードをリセットすると、リモコンとスピーカーの接続も
切れる。接続済みの状態でレポートを確認したいときは、DTR/RTS に触れずに
ポートを開いて読むだけにする。`/dev/cu.*` はオープンしても DTR を立てない
ので、リセットは起きない。

**書き込みがたまに失敗する**

`A fatal error occurred: No more data to read from the serial port.` で
失敗することがある。ポートを他のプロセスが掴んでいなければ、そのまま
再実行すれば通る。
